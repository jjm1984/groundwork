# Name the Gaps

Adapted from prior methodology work. The rule it operationalizes, in the source's own words: *"the gap named... is just as important as the knowledge, and the shape... should reflect the gaps and not build symmetrical for aesthetics."* Ask, often: what is missing, what haven't we thought of, what are we not looking at because the convenient answer was easier to follow.

## The four areas — check all four, every real run

1. **The current task.** Before calling it done: what did the chosen approach not consider? What alternative got dropped because it was harder, not because it was wrong?
2. **The project's own documentation.** `docs/open-questions.md`, `deferred.md` — are they still accurate, or has real work moved past them without anyone checking whether they're still open?
3. **Process.** `roles/`, `abilities/`, `skills/`. Where a file has no open questions noted, is that because nothing is unresolved, or because no one has looked?
4. **Whatever was just built.** The newest work this session, checked against the nearest comparable prior work. An asymmetry between them is a candidate finding, not automatically a defect.

## The symmetry check — run this specifically

Even coverage is suspicious, not reassuring. If one thing in a set has something a comparable one lacks (a test, a doc section, a review step), that's either a real gap or a reason the pattern genuinely doesn't apply here — until one of those two is written down, treat it as neither confirmed nor dismissed. Don't fill it in just to make things look even; that manufactures the false completeness this skill exists to prevent.

## Steps

1. **State which of the four areas this run is actually checking.** "Look for gaps" with no stated scope is exactly the kind of instruction that lets a shortcut pass as complete.
2. **Keep going past the first comfortable finding.** The convenient gap to name is often not the real one — it's the one that was already half-visible.
3. **Route each finding to whatever already owns that kind of gap** — `deferred.md` (with a trigger), an open question in `docs/open-questions.md`, an entry in `lessons.md`. Don't invent a new gap registry.
4. **Name what wasn't checked.** Say plainly which of the four areas this run skipped, and why.

## What this does not do

It doesn't fill the gaps it finds, and it doesn't decide on its own authority whether an asymmetry is a real defect or a deliberate difference — that's routed to whoever's accountable for the thing in question.
